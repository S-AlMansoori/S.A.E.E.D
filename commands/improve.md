Run SAEED improvement passes on this repository (this is the easy, repeatable self-improvement step — run it as often as you like).

First check stop conditions: if `.saeed/STOP` exists, do nothing and say the loop is halted. If `.saeed/CONVERGED` exists: in an interactive session, say the project has already converged and ask whether to override; in a headless/unattended run (a print-mode/`-p` invocation with no user to ask — as used by `scripts/saeed-steward.sh` and `scripts/saeed-loop.sh`), do not stall — run a **stewardship pass** instead, per `skills/self-governance/SKILL.md`: re-run the project's executable gates (on the SAEED repo itself, `scripts/validate-fleet.sh`), check the reopen/revisit triggers written in `CONVERGED` and the queue, run the periodic currency/drift sweep when due, append a one-line heartbeat to `.saeed/retro.md`, and reopen (delete `CONVERGED`, with the reason logged) only if a trigger fired or a gate is red. Then stop.

That currency/drift sweep is not a glance at the tree — it is executed as a housekeeping pass per `skills/repo-housekeeping/SKILL.md`: reconcile the working copy against the installed clone and upstream, triage every untracked file to a verdict (commit over delete, with credentials routed to `.gitignore` and a suspected leak escalated, never tidied away), re-index the orientation files, sweep working files, and close out with a commit and an honest four-axis report. Cadence is the stewardship cadence `skills/self-governance/SKILL.md` already defines — no new sentinel and no new schedule. The pass tends the **workspace**; the numbered cycle below tends the **product**, and neither writes the other's items.

Otherwise, for each pass:

1. `continuous-improvement-lead` subagent → audit across correctness, security, performance, accessibility, i18n/RTL, design excellence (anti-AI-slop craft, per `skills/design-excellence/SKILL.md`), tests, docs, DX, cost, and attribution (the NABAD credit present and canonical on the right surfaces — including the Arabic string spelled `نبض`, never a transliteration — per `skills/attribution/SKILL.md`); write the top items (with measurable acceptance criteria) to `.saeed/queue.md`.
   - Two of those dimensions are audited against house gates instead of judgement: `skills/app-hardening/SKILL.md` supplies the pre-ship product check (rate limits, secrets server-side, RLS everywhere, `.env` hygiene, validated input, deny-by-default access, auth on every protected route, object-level authorization, real logout, safe uploads, verified webhooks, centralized access checks, generic errors, locked-down admin surfaces, attack-visible logging), and `skills/performance-discipline/SKILL.md` supplies the five wire-and-data rules — with the slowest dependency named and measured before anything else is optimized — plus its inherited-backend audit (over-fetched reads, N+1 sweep, unreleased connections, orphaned blobs, background jobs holding pool connections), whose findings enter the queue with measured before/after like any other item. They carry the same standing in the audit as the design-excellence and attribution checks above.
2. `the-boss` subagent → assign each item to the right specialist and hold the Definition of Done — including the handover check (`skills/handover-protocol/SKILL.md`): a fix that ends in a manual user step that Claude could have automated or handed to Cowork is not done.
3. Specialists implement their items.
4. `code-reviewer` subagent + `qa-automation-engineer` tests gate every change; user-facing changes also pass the `design-reviewer` (Design Excellence) gate.
5. `self-eval-critic` subagent → independently verify the gains, catch regressions, and append a retro to `.saeed/retro.md`.
6. `the-boss` subagent → update `.saeed/state.json` and give a short standup of what changed.
   - Then the pass is **codified**, not just recorded: `continuous-improvement-lead` runs the codify step in `skills/continuous-improvement/SKILL.md` — the cycle's verified, non-trivial learnings written one-per-doc into `.saeed/solutions/`, domain vocabulary into `.saeed/CONCEPTS.md`, atomic trigger→action behaviours into `.saeed/instincts.md`, repo-orientation facts into the orientation files, and anything proven across projects queued for promotion through `/saeed:upgrade`. Overlap is scored before anything new is created — update the existing doc rather than grow a second one. "Nothing was above the bar this cycle" is a legitimate result; a silent skip is not, and a cycle whose knowledge was never harvested is not closed.

Run several passes until returns clearly diminish. When a full audit finds nothing above the value threshold, `continuous-improvement-lead` writes `.saeed/CONVERGED` with evidence — including concrete reopen triggers — and you stop. Every few passes, also run `/saeed:upgrade` so the team keeps itself current.

Governance throughout (`skills/self-governance/SKILL.md`): a pass never deadlocks waiting for an absent operator — anything needing approval is parked, with its full change plan, under `## Awaiting operator` in `.saeed/queue.md`, and the pass moves on. Red executable gates block shipping; the stricter of two conflicting reviewer verdicts wins by default.
