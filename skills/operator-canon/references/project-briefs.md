# Owner project briefs — what is published, and where the rest lives

A brief binds **only the project it is identified with** (rule 2, and the predicate in `SKILL.md`). It records the operator's intent at a date — never proof that anything was built, tested, priced or submitted. When the project's own spec or `.saeed/` record is newer, that wins.

## Where briefs live

- **Private or unreleased projects:** the brief lives in that project's own repository (its spec and `.saeed/`) and in the owner's private, gitignored evidence for this plugin. It is never copied here — this repository is public (rule 8), and a plan for an unreleased product, a security or financial design, or a project's coordination rules is private until the operator approves publishing it.
- **Projects whose instructions name their own coordination board:** those rules are read from that project and its board at the time of work, and are never applied elsewhere.
- **Published here:** only briefs whose subject is already public and whose content the operator has approved for publication.

Working on an owner project with no published brief: read the project's own spec and `.saeed/` first; ask the operator rather than reconstructing intent from memory or from another project's brief.
